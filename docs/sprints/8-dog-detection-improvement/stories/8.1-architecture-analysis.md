## Architektura modelu

### Wybrany model: YOLOv8m (COCO pretrained)

**Uzasadnienie wyboru:**
- YOLOv8m to optymalny kompromis między dokładnością a prędkością
- Pretrenowany na COCO 80 klas (klasa 16 = dog) — nie wymaga fine-tuningu
- Obsługiwany przez bibliotekę `ultralytics` z aktywnym wsparciem
- Działa bez GPU (tryb CPU do testów)

**Porównanie wariantów YOLOv8:**

| Model | Parametry | mAP COCO | Prędkość (CPU) | Wybór |
|-------|-----------|----------|----------------|-------|
| YOLOv8n | 3.2M | 37.3 | ~80ms | za mała dokładność |
| **YOLOv8m** | **25.9M** | **50.2** | **~234ms** | **✓ wybrany** |
| YOLOv8l | 43.7M | 52.9 | ~375ms | zbyt wolny dla pipeline |

## Specyfikacja wejść/wyjść

### Wejście

| Parametr | Wartość | Opis |
|----------|---------|------|
| Format | `np.ndarray` (BGR) | OpenCV standard, uint8 |
| Kształt | `(H, W, 3)` | Dowolny rozmiar — YOLO skaluje wewnętrznie |
| Preprocessing | Wewnętrzny w ultralytics | Letterbox resize → imgsz×imgsz, normalizacja 0–1 |
| imgsz | 640 (domyślnie) | Rozmiar wewnętrznego resizu |
| Kanały | BGR | ultralytics obsługuje BGR z OpenCV poprawnie |

**Uwaga:** Biblioteka ultralytics przyjmuje tablice numpy w formacie BGR (OpenCV) i samodzielnie przeprowadza letterbox resize oraz normalizację. Nie ma potrzeby ręcznego preprocessingu klatki.

### Wyjście

| Pole | Typ | Opis |
|------|-----|------|
| `bbox` | `tuple[int,int,int,int]` | (x, y, w, h) w pikselach oryginału |
| `confidence` | `float [0.0, 1.0]` | Pewność detekcji |
| `class_id` | `int` | 0 dla fine-tuned, 16 (COCO dog) lub niestandardowy |
| `class_name` | `str` | Zawsze "dog" |

## Parametry konfiguracyjne

| Parametr | Domyślnie | Opis |
|----------|-----------|------|
| `confidence_threshold` | 0.5 | Minimalna pewność detekcji |
| `iou_threshold` | 0.45 | NMS IoU threshold |
| `max_detections` | 10 | Maksymalna liczba psów na klatce |
| `imgsz` | 640 | Rozmiar wewnętrznego resizu |
| `dog_class_id` | 16 | ID klasy psa (16=COCO, 0=fine-tuned) |
