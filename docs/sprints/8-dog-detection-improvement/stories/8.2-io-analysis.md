# Story 8.2 — Naprawa predict() — filtrowanie psów

**Sprint:** 8 — Dog Detection Improvement
**Status:** Done
**Priorytet:** High

---

## Opis

Naprawa błędu w metodzie `predict()` klasy `BBoxModel`: metoda zwracała wszystkie klasy COCO oznaczone jako "dog", zamiast filtrować tylko psy (klasa 16 w COCO).

---

## Znaleziony błąd

**Plik:** `packages/models/bbox.py`

**Problem:** Metoda `predict()` pobierała wszystkie detekcje z YOLO (samochody, ludzie, koty itp.) i przypisywała im `class_name="dog"`. Tylko oddzielna metoda `filter_dogs_only()` działała poprawnie.

**Skutek:** Przy użyciu standardowego modelu COCO `yolov8m.pt`, metoda `predict()` mogła zwracać fałszywe detekcje psów dla innych obiektów.

---

## Wprowadzone zmiany

### 1. `BBoxConfig` — nowe pole `dog_class_id`

```python
dog_class_id: int = 16  # 16 = COCO dog, 0 = fine-tuned model
```

Umożliwia obsługę zarówno modeli pretrenowanych na COCO jak i fine-tunowanych.

### 2. `predict()` — filtrowanie po `dog_class_id`

Metoda teraz filtruje detekcje po `cls_id == self.config.dog_class_id`. Zwraca tylko psy.

### 3. Usunięto `filter_dogs_only()`

Metoda była duplikatem logiki `predict()` z dodatkiem hardcoded `coco_dog_class_id=16`. Po naprawie `predict()` jest ona redundantna.

### 4. Naprawa `predict_with_visualization()`

Ta sama naprawa — teraz filtruje po `dog_class_id`.
